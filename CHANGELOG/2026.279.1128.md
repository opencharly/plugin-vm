# 2026.279.1128 — fix(vm): bound every teardown libvirt RPC so `vm destroy` cannot hang unkillably (#800) — successor to #69

## Summary

`charly vm destroy <vm> --domain <bed>` **hung indefinitely and resisted SIGTERM**, leaving the libvirt domain `running` (opencharly/charly#800) — a blocker for every `check-kubevirt-vm` bed run, worked around only with `virsh destroy`.

**Root cause (R1).** The teardown's libvirt RPCs are **context-less in go-libvirt**: they have no request timeout of their own. When `virtqemud` is wedged (or a snapshot delete stalls on an in-use backing), the RPC blocks in the socket read **forever**; charly's installed SIGTERM handler then runs its cleanups **behind the blocked dispatch goroutine**, so the signal does not unwind the call and only `SIGKILL` lands — exactly the observed signature (timed out, domain still up, `kill -9` required).

**Fix.** `boundedRPC` / `boundedRPCValue` give each teardown RPC a hard wall-clock bound (`teardownRPCBound`, 30 s) and, on timeout, return a **NAMED** error WITHOUT waiting for the wedged call. Applied to **every** RPC the destroy path reaches, each as its own bounded method:

| method | libvirt RPC |
|---|---|
| `lookupDomain` | `DomainLookupByName` |
| `destroyDomain` | `DomainDestroy` |
| `shutdownDomain` | `DomainShutdown` |
| `undefineDomain` | `DomainUndefineFlags` |
| `snapshotNum` | `DomainSnapshotNum` |
| `snapshotNames` | `DomainSnapshotListNames` |
| `snapshotLookup` | `DomainSnapshotLookupByName` |
| `snapshotDelete` | `DomainSnapshotDelete` |

The bound is generous enough that a busy-but-live `virtqemud` finishes.
