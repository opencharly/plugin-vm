# 2026.267.1012 — feat(vm): ISO console-install mode — boot the medium's own interactive installer

## Summary

An `iso` VM whose entity declares **no** `source.installer` now builds in
**CONSOLE mode**: it boots the medium to its own INTERACTIVE installer on a BLANK
disk and is driven over its console — no answers volume is rendered. The drive is
the shared `sdk/kit` console-wizard recipe, invoked through `spice: wizard`, the
SAME recipe that drives a physical machine over a JetKVM (R3).

This is the enabling change for `check-omarchy-vm-console` in distro-omarchy.

### `vm_build_resolve.go` + `vm_iso_engine.go`

The console-vs-unattended decision is ONE pure function, `isoConsoleMode`, and
the resolve guard is a second pure predicate, `isoDistroInstallerRequired`, both
shared so the build engine and the guard cannot drift:

- `vm_build_resolve.go`: the guard rejects a missing `installer:` format only
  when an unattended install will run.
- `vm_iso_engine.go`: console mode renders **no** seed and creates a blank qcow2;
  the blank-disk + build-stamp orchestration is extracted to `ensureBlankDisk`,
  called by BOTH the console and unattended paths (R3).
- `isoConsoleMode` was moved ABOVE `BuildIsoVM`'s doc comment so each declaration
  keeps its own doc (B18).

### Also resolved (R1 zero-warnings)

Three pre-existing `golangci-lint` findings in files this branch touches are

serial-log error drops its trailing newline, and `vm_diagnose.go`'s switch
