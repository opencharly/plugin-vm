# 2026.267.2103 — fix(vm): skip the per-domain seed re-pack for a console-mode iso VM

## Summary

Fixes TWO defects the CONSOLE-mode ISO VM feature (opencharly/plugin-vm#41)
introduced, both surfaced by a live consumer-bed run.

### 1. The per-domain seed re-pack (`shouldRepackIsoAnswers`)

`charly vm create` on a console-mode iso VM failed with

```
rendering the per-domain answers volume: no rendered answers found at
image/omarchy-liveinstall-vm/.seed-answers.json — run `charly vm build` first
```

`shouldRepackIsoAnswers` unconditionally re-packed the per-domain answers volume
for any `iso` source. Gated on `isoConsoleMode`: a console-mode VM has no answers
volume, so the re-pack is skipped.

### 2. The libvirt seed CD-ROM (`runVmSpecCreate`)

After (1), the domain definition still referenced `seed.iso`, so libvirt refused
to start the domain:

```
starting domain: Cannot access storage file
'.../charly-check-omarchy-vm-console/seed.iso': No such file or directory
```

The iso seed-path assignment is now gated on `!isoConsoleMode(spec)`, so a
console-mode VM has NO seed path — and the libvirt bridge already omits the seed
CD-ROM when the path is empty.

Unattended iso VMs are unchanged.

### 3. Test hygiene

`vm_create_orchestrate_b12_test.go` renamed a local variable that shadowed the
imported `spec` package (a B18 smell).
