# 2026.240.1844 — refactor(ovmf): delete the second ovmf_distro_aliases copy

## Summary

The other half of the duplication, and the last leg of batch **B4**'s `ovmf_family` item.

This file carried a **byte-identical** copy of `charly/charly.yml`'s `ovmf_distro_aliases` table —
verified line for line — so every new distro had to be added in both places, and adding it to only
one was silent:

```
$ diff <(sed -n '144,153p' charly/charly/charly.yml) \
       <(sed -n '42,51p' plugin-vm/candy/plugin-vm/build_defaults.yml)
BYTE-IDENTICAL
```

Dead since `opencharly/sdk#178`: the OVMF resolver reads `spec.DistroOvmfFamilies`, generated from
`#Distros[id].ovmf_family`.

## The keys test needed real changes, not a deletion

`build_defaults_keys_test.go` exists to make unread-key **regrowth** fail loudly. It asserted
`ovmf_distro_aliases` twice — as an *allowed* key, and as a **required** one:

```go
t.Errorf("build_defaults.yml is MISSING %q, which the OVMF resolver requires (it panics without it)", k)
```

Both statements are now false. So:

- the allowed set narrows to `ovmf_paths` — which turns a reappearing `ovmf_distro_aliases:` into
  exactly the regrowth this test exists to catch, rather than something it would wave through;
- the decode control drops its emptiness check, since nothing panics on the key's absence any more.

That second point matters: leaving the check would have made the test fail for the right reason with
the wrong explanation ("the resolver panics on this") long after the panic was deleted.
