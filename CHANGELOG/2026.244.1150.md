# 2026.244.1150 — feat(vm): the snapshot composite verbs — create-consistent and revert-and-start (§5.3.1)

## Summary

Implements the §5.3.1 snapshot composite verbs in candy/plugin-vm (the omarchy PR-evaluation plan's batch accelerator):

- **`charly vm snapshot create-consistent <vm> <name>`** — ONE step that produces a GUARANTEED-consistent snapshot: strict agent precondition (qemu-guest-agent must be reachable) → quiesced `CreateSnapshot` (`Quiesce=true`, registry records `Quiesced=true`) under a new `strictQuiesce` flag that disables `createExternalSnapshot`'s best-effort fallback. libvirt's quiesce flag freezes + snapshots + thaws ATOMICALLY — no manual freeze/thaw, no silent fallback: if the agent is unreachable OR the quiesce flag fails, the command FAILS (the exact distinction from `create --quiesce`, whose external path retries without the flag). A stopped/absent domain is inherently consistent → plain create. Internal mode + running domain → hard error (qemu-img cannot mutate a live qcow2).
- **`charly vm snapshot revert-and-start <vm> <name>`** — encapsulates the offline-domain semantics: `stopVmDomain` (the authoritative backend-probe stop; already-stopped = clean no-op) → `RevertSnapshot` (registry/mode dispatch; domain now offline so both the qemu-img internal revert and libvirt external revert can run) → **`startVmDomain`** (new, config-free backend-probed start — the symmetric counterpart of `stopVmDomain`, deliberately NOT `startVM` which resolves the backend via the project-config reverse channel; the snapshot surface is config-free by construction). The order is pinned by the injectable `revertAndStartSteps` seam (unit-tested) and proven end-to-end by a real-libvirt offline-revert+restart test.

- **`--domain <deploy-name>` on ALL snapshot subcommands** (create, create-consistent, list, delete, revert, revert-and-start, promote) — targets a check bed's per-deploy domain instead of the entity's own domain. The snapshot surface is keyed on the kind:vm ENTITY name (paths + registry + `charly-<name>` domain lookup), but a check bed's live domain is named after the DEPLOY (`charly-<BedDomain>`, #33/P33) — the entity's own domain does not exist for a bed. `snapshotVmName` substitutes the deploy name for the entity name across registry, disk paths, and domain lookup, so the snapshot-anchored check-run mode (plugin-check) can capture and revert the BED's domain.

- **`vm destroy` teardown of snapshot-carrying domains** — the destroy op now enumerates and deletes the domain's libvirt snapshots (`DomainSnapshotNum`/`DomainSnapshotListNames`/`DomainSnapshotDelete`) before `undefineDomain`. A domain with snapshots cannot be undefined ("cannot delete inactive domain with N snapshots"); the snapshot-anchored check-run mode leaves a golden snapshot on the bed's domain, so teardown (batch end) must remove the snapshot records first. Proven live: `vm destroy omarchy-vm --domain check-charly-omarchy-vm --if-exists` on the snapshot-carrying bed domain succeeds (the fresh-lane cleanup step PASSED with the snapshot present).

Spec pin bumped to v0.2026244.1013 (the merged `Snapshot`/`Variants` deploy fields + `#VmSnapshotPolicy`/`#VmVariant` types).

### Live proof — create-consistent SUCCESS path on a real guest-agent domain (the validator's A3 ask)

The success path (running domain + qemu-guest-agent → strict quiesce → snapshot) was exercised live on a real arch VM with a working guest agent. **This surfaced and fixed a real correctness bug**: the original composite pre-froze the guest filesystems (`FsFreeze`), then passed `Quiesce=true` into `CreateSnapshot` — libvirt's quiesce flag tried to freeze AGAIN, and qemu-guest-agent REJECTS the double-freeze (`command has been disabled`). `createExternalSnapshot`'s best-effort fallback then silently created a NON-quiesced snapshot while the registry recorded `Quiesced=true`. The fix (this PR's head): the composite pings the agent (strict) and lets libvirt's quiesce flag freeze+snapshot+thaw atomically under `strictQuiesce` (fallback disabled).

Before the fix (the silent fallback + registry lie):

```
$ charly vm snapshot create-consistent arch test-consistent
note: quiesce failed (qemu-guest-agent not available?); retrying without --quiesce
created consistent external snapshot "test-consistent" on vm "arch"
$ cat .../charly-arch/snapshots/registry.json | jq .snapshots["test-consistent"].quiesced
true   # LIE — the fallback created a NON-quiesced snapshot
```

After the fix (strict atomic quiesce — no fallback note, honest registry):

```
$ charly vm snapshot create-consistent arch test-consistent
created consistent external snapshot "test-consistent" on vm "arch"
  disk: /home/atrawog/.local/share/charly/vm/charly-arch/snapshots/test-consistent/disk.qcow2
$ cat .../charly-arch/snapshots/registry.json | jq .snapshots["test-consistent"].quiesced
true   # HONEST — libvirt's quiesce flag succeeded (no fallback note)
```

The strict failure path (running domain WITHOUT an agent → hard error, no fallback) is pinned by `TestCreateConsistent_StrictAgentOnRunningDomain` (real libvirt).
