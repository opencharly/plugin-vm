# 2026.314.1526 — refactor(schema): derive the vm word sets from vocabulary tables

## Summary

Convert the two inline `|` word unions in `candy/plugin-vm/schema/vm.cue` to the §10.1 S3
vocabulary-table idiom, so each closed set of words has ONE home and the enum an author meets
is `or()` of that table's derived word list:

```
_method  (27 words) -> _methodWord -> #LibvirtVerbInput.method
_action  ( 3 words) -> _actionWord -> #LibvirtVerbInput.action
```

That is the 2 `union` rows `design/dpat-baseline.tsv` records for
`plugin-vm/candy/plugin-vm/schema/vm.cue` — two disjunctions, one row each, both pure word
lists. No other row names this repo, so this PR retires the whole of its census debt (2 of 2;
0 left).

**How this repo was picked.** It is the second unit of this batch, from the
entirely-word-list set re-derived from `git show origin/main:design/dpat-baseline.tsv` —
strip a trailing `@go(...)` and enclosing parens, drop an empty trailing alternative, then ask
whether every alternative is a quoted string. Ranked by row count with ties broken by word
count, this batch's three are `plugin-appium` (2 rows, 51 words — opencharly/plugin-appium#12),
`plugin-vm` (2 rows, 30 words — THIS PR) and `plugin-cdp` (2 rows, 25 words).

**The one judgement this repo needs: the method catalog is a MAP, not a switch.** Every other
swept sibling routes its methods through a `switch`, so its invariant reads case arms. This
plugin's `dispatchLibvirtVerb` looks the method up in `libvirt_methods.go`'s `libvirtMethods`
map and turns the entry into an in-process CLI invocation — a test that looked for a
`switch method` would find no arms at all and report all 27 methods as phantoms. The
invariant therefore reads the MAP's keys plus the ONE pre-dispatch comparison, and it pins two
things the map carries as data that no type checks: each entry's `Path` (a copy-pasted path
dispatches a DIFFERENT subcommand under this method's name) and each entry's `Required` names
(which are plugin-INPUT keys, or the one documented shared step-level `target`).

The two sets stay two tables because they are two vocabularies: `method` is the libvirt probe
catalog the dispatcher reads, `action` is the DETACHED recorder's bracket
(`start|stop|status`, session_method.go's `switch in.Action`). Each is pinned against its OWN
router, in both directions.

No word moves: the accepted sets are IDENTICAL before and after — 27 methods, 3 actions — read
from the compiled CUE on both sides (226-case differential below). The umbrella leg — the pin
plus the emission-diffed census — is the lead's, by emission; this PR touches neither
`design/dpat-baseline.tsv` nor the umbrella.
