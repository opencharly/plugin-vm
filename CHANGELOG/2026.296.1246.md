### The provider class

`vm_backend_class.go` defines one `vmBackendProvider` interface and ONE registry keyed by the schema-owned `spec.VmBackends` (generated from `#VmBackendName`):

```
vmBackendProviders = map[spec.VmBackend]vmBackendProvider{
    vmBackendLibvirt: libvirtBackend{},
    vmBackendQemu:    qemuBackend{},
    vmBackendKrun:    krunBackend{},
}
```

- `resolveVmBackendProvider`: `auto` walks the schema order over the auto-detectable providers; an explicit word resolves to its provider and must be `Available()`. `krun` is explicit-only (`AutoDetectable() == false`), matching `deploykit.ResolveVmBackend`.
- `vmBackendHolder`: asks every provider in schema order; the first claim wins. This is the ONE authoritative "which backend actually holds this VM" probe (#69/#77), now class-generic.
- Every dispatch site resolves a provider: `resolveVmBackendPlugin`, `startVM`, `startVmDomain`, `stopVmDomain`, `destroyVmDomain`, `destroyVmDomainOnBackend`, the `provider.go` create/validate op, `VmConsoleCmd`, `VmListCmd`, `VmScreenshotCmd`, and the GPU hostdev precondition.
- `libvirtBackend` / `qemuBackend` hold the existing arms; the qemu holder now requires a qemu artifact (`command` or `qemu.pid`) in the state dir, so a krun state dir (`krun-plan.json`) can never be torn down through the qemu arm.

### `vmbackend:krun`

`vm_krun_plan.go` is the pure mapping; `vm_backend_krun.go` is the lifecycle. The mapping, from the plan's W3.4:

| VmSpec | Emitted | Test that fails when removed |
|---|---|---|
| `ram` | `--memory <ram>`, `--memory-swap <ram>` (swap disabled) | `TestKrunPlanRAMSplit` |
| `ram`, `krun.ram_headroom_mib` | `krun.ram_mib = ram - headroom` (guest RAM is not the container limit) | `TestKrunPlanRAMSplit`, `TestKrunPlanHonoursAuthoredHeadroom` |
| `cpu` | `krun.cpus=<n>` and NO `--cpus` | `TestKrunPlanCPUsIsAnnotationNotFlag` |
| `krun.network: passt` | `krun.use_passt=1` (absent for `tsi`) | `TestKrunPlanPasstAndKernel` |
| `krun.kernel: image` | `krun.custom_kernel=1` (absent for `stock`) | `TestKrunPlanPasstAndKernel` |
| a systemd guest | `KRUN_INIT_PID1=1` + `--ulimit nofile=524288:524288` | `TestKrunPlanSystemd` |
| SSH | published `127.0.0.1:<host>:22` | `TestKrunPlanSSHLoopback` |
| `network.port_forwards` | published `127.0.0.1:<host>:<guest>` | `TestKrunPlanPortForwards` |
| per-domain key | `KRUN_SSH_PUBKEY=<pub>` (the image installs it) | `TestKrunPlanSSHPubKey` |

The argv is produced by the REAL engine class servant (`spec/container.InvokeEngineOp`, op `start_plan`), with the containerd target's `--address` / `--namespace` inserted after the binary and the rootful prefix before it. `TestKrunStartArgvThroughTheEngineClass` asserts `--runtime krun`, the memory args, the annotations, the loopback port, the env handoff (`-e KRUN_INIT_PID1=1`, `-e KRUN_SSH_PUBKEY=...`), the image-last shape, and the ABSENCE of `--cpus`.

Stop is `systemctl poweroff` over the managed SSH alias (the image's `krun-poweroff` hook), then a bounded verify that the container left `running`. No signal is ever sent, including under `--force` (`TestKrunStopPowersOffNeverSignals`, `TestKrunStopForceStillPowersOff`). Start distinguishes a stopped container (`start`) from an absent one (re-run the recorded argv), so the writable snapshot and the name are preserved (`TestKrunStartStartsAStoppedContainer`).

The SSH alias is **single-sourced**: `vmManagedSSHAlias` is used by both `publishVmSshAlias` (the publisher) and `runKrunCreate` (the recorder), and `KrunSSHAlias` carries the exact published value into the state that `Stop` reads. `TestKrunRecordedAliasEqualsPublishedAlias` fails if the two diverge.

Refusals:
- krun + NVIDIA: the render-server sandbox dev-binds only `/dev/dri` (NEEDS UPSTREAM). The check fires BEFORE the generic PCI-hostdev refusal, so the message names the upstream limit (`TestKrunPlanRefusals`, `TestKrunNVIDIARequired`).
- krun GPU memory floor: a virtio-GPU guest below 1024 MiB of guest RAM OOM-kills Vulkan compute (`TestKrunPlanRefusals`).
- screen capture: crun/krun exposes no host-capturable framebuffer (`TestKrunScreenshotRefused`).
- `snapshot:`: refused with a named pending extraction. A krun snapshot is a containerd commit + state-volume clone, and W2 seam 2 lives in crabbox's `internal/providers/containerd` package, which Go's internal rule forbids this module from importing. Writing a second implementation would be the R2 duplication this provider exists to avoid. Filed as opencharly/crabbox#21 (`refuseKrunSnapshot`, `TestRefuseKrunSnapshotNamesTheExtraction`).

### Placement

The class is IN-PACKAGE, not a `plugin.providers` capability. `charly/provider.go` has no `ClassVMBackend`, and `spec`/`sdk` carry no `vmbackend` op envelope, so an out-of-process `plugin-vm-krun` could register a word that nothing dispatches. The krun provider is a separate FILE SET (`vm_backend_krun.go` + `vm_krun_plan.go`), so promoting it to its own repo once the core class exists is a move, not a rewrite. This is stated here because the plan names a `plugin-vm-krun` repo; creating it now would produce a repo that cannot participate in dispatch.

### Round 1: the BLOCK, the rebuttal, and the control fix

The validator BLOCKed on: "the recorded SSH alias is not the alias that gets published". **The premise is false.** At the blocked head `b2e1889`:

```
$ git grep -n "Alias:.*VmSshAlias" b2e1889 -- "*.go"
b2e1889:vm_create_orchestrate.go:455:		Alias:          VmSshAlias(domainName),

$ sed -n '40,42p' $(go env GOMODCACHE)/github.com/opencharly/spec@v0.2026296.1036/spec/vm_domain.go
func VmSshAlias(vmName string) string {
	return "charly-" + vmName
}

$ git grep -n "vmDomainName := " b2e1889 -- "vm_create_orchestrate.go"
b2e1889:vm_create_orchestrate.go:33:	vmDomainName := "charly-" + name
```

`publishVmSshAlias` was called with the bare `name` and applies `VmSshAlias` internally, so it published `charly-<name>`; the state recorded `plan.Name == req.VmDomainName == "charly-" + name`. The two values were already equal, and no behaviour defect existed.

The REAL finding is the missed control: nothing executable tied the two values, so the invariant lived two calls deep and a future change could break it silently. The root fix makes it structural: `vmManagedSSHAlias` is the single alias function used by both the publisher and the recorder, and `KrunSSHAlias` carries the exact published value. `TestKrunRecordedAliasEqualsPublishedAlias` fails if they diverge (mutation-killed above). The validator's two non-blocking concerns were also fixed: the env-to-argv handoff is now asserted through the real engine servant, and the `destroyVmDomainOnBackend` seam gets a direct test for an empty/unknown backend (it was already called by the two libvirt destroy tests in `vm_destroy_test.go`).
