# 2026.250.1520 — libvirt: add the session method (Cutover E E-2)

## Summary

Adds the `session` method to the `libvirt` verb (plan `nested-capture-architecture.md`, Cutover E, unit 2): the host-side detached VM framebuffer recorder — the non-SPICE VM display path (libvirt RPC `DomainScreenshot` polling), the libvirt analogue of the landed session methods (plugin-vnc E-1, tag v2026.250.1257; plugin-cdp E-3, tag v2026.250.1422). It is implemented over the runner's GENERIC background-session service (plugin-check's compiled-in `verb:session` seam); NO core changes — the genericity proof for the VM venue.

- **schema/vm.cue** — `session` joined the `method` enum + per-verb modifiers `action`/`fps`/`session_id`/`state_dir`/`artifact_dir`/`log_dir`/`venue`/`phase` (mirroring `#VncInput`/`#CdpInput`); params regenerated via the documented pipeline (byte-identical regen proven on the pre-change schema).
- **session_method.go** — provider-side dispatch: runSession (`start|stop|status`), buildSessionSpawn (this plugin's own binary in recorder mode + the `CHARLY_LIBVIRT_*` env), submission over the EXISTING InvokeProvider reverse leg — class `verb`, word `session`, `ops.OpExecute`. Plan-step sessions fall back to `session_id: "default"` + a provider-owned temp state dir.
- **recorder.go** — the detached recorder engine: dials the host-pre-resolved libvirt endpoint, gates on the domain running, polls the framebuffer via the plugin's EXISTING `DomainScreenshot` drain (incl. its virsh fallback for the virtio-gpu RPC-stream framing break) at fps (default 5, cap 100) into `<state_dir>/frames.mjpeg`, and on SIGTERM/SIGINT finalizes the `FINAL` marker + the shared `#EvidenceRow` `row.json`.
- **cmd/serve** — hidden recorder mode (`CHARLY_LIBVIRT_RECORDER=1`) on the existing binary (the sdk.Main dual-mode shim).
- **provider.go** — `session` dispatched before the Kong tree; `vmEnv` gains `venue`; `resolveLibvirtSessionEndpoint` builds the endpoint off the deployment VM name + URI and gates on the live deployment (domain exists + running → else SKIP N/A).
- **Placement fix (f35d95b)** — the reverse leg is served placement-invisibly: `sdk.ExecutorForInvoke` resolves the in-proc executor client for the COMPILED-IN placement (plugin-vm's canonical placement — `sdk.NewCheckContext` only works out-of-process where the go-plugin broker exists).
- **Recorder-binary fix (2430cf4)** — the compiled-in spawn gap the live run exposed: session start submitted `os.Executable()`, which for the canonical compiled-in placement is the CHARLY binary — no recorder shim (the shim lives in this plugin's own serve binary). `resolveRecorderExe` now prefers the plugin's serve twin on the baked-plugin search path with the host loader's own precedence: `$CHARLY_PLUGIN_DIR` first, then the FHS `/usr/lib/charly/plugins` — only for a packaged install (executable under `/usr/bin` or `/usr/local/bin`; issue #328 — a dev binary must not reach into the installed package's plugins), `$CHARLY_PLUGIN_ONLY=1` dropping the FHS leg. Falls back to the current binary for the out-of-process placement (where it IS the shim carrier).
- **go.mod** — NO pin changes (sdk v0.2026250.527, spec v0.2026250.523 already carry the seam contract).
