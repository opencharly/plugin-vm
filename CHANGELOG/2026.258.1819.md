### The root fix in commit 5

The create path threads `c.Domain` into the identity-scoped resolve — but the **stop and
destroy** paths called `lookupVMClaimant(c.Box)` with NO identity. For a sibling-sharing
entity that call is AMBIGUOUS, so `FindVMClaimant` returns `false` (spec's deliberate
"never pick a map-order winner" guard), `releaseResourceClaim` never ran, and the acquired
lease leaked: the preempted GPU holder was never restored, and a sibling's lease could be
mis-scoped instead. So the original fix was **incomplete** — it fixed the acquire half and
left the release half entity-scoped.

- `hostConfigResolve(entity, claimantID)` now takes the claimant identity as an **explicit
  argument at every call site** — no hidden empty-string fallback. The `hostConfigResolveFor`
  wrapper of commits 2 is DELETED (it does not exist in this tree; the grep below proves 0
  references).
- `lookupVMClaimant(entity, identity)` threads the caller's `--domain`; `VmStopCmd` and
  `VmDestroyCmd` now pass `c.Domain`, so the release brackets exactly the lease create
  acquired.
- The merge + resolve collapse into ONE seam, `resolveClaimant` (`vm_host_seams.go`) — the
  single abstraction create/stop/destroy share (R3).
- The stale `startVM` comment claiming it is "Shared by … candy/plugin-preempt" is corrected
  (that plugin's `startVMPlugin` reaches the vm plugin's `start` op over the reverse channel
  directly, config-free) — a comment↔reality divergence, fixed in the same change (R1).
