# 2026.246.0545 — feat(vm): wire the clone build path end-to-end

## Summary

Wire the `source.kind: clone` VM build path end-to-end. `BuildClone` (the VM-on-VM primitive: materialize a fresh qcow2 with the parent snapshot's external disk as backing chain, bump the parent snapshot refcount, regenerate the cloud-init seed ISO with a fresh instance-id) was implemented but never connected:

- `knownVmSourceKinds` excluded `clone`, so `charly vm build` rejected clone entities with "unsupported source.kind".
- The build dispatch had no `clone` case.
- `charly vm clone` only wrote the kind:vm declaration then printed a "rerun charly vm build" hint.

This PR connects it: `clone` joins the known kinds with a pass-through resolve case (validating `from_vm`/`from_snapshot` at resolve time), the dispatch gains the `clone` case calling `BuildClone`, the build drive is extracted into `runVmBuildDrive` shared by `VmBuildCmd.Run` and the clone command's `--build` leg (R3 — one drive, no duplicated dispatch), and `charly vm clone --build` now drives the standard build pipeline. It also adds `charly vm snapshot capture-declared`, which captures every snapshot declared in the entity's `snapshot:` block (idempotent — already-captured snapshots are noted and skipped) — the declarative twin of the check-bed snapshot policy, making the entity block the single declaration point for a provisioned base VM.

### Findings for follow-up — each routed to a NAMED task of the VM-box cutover (plan/vm-from-box-layering.md)

1. **Error masking** (`resolveVmBuildEntity`/`noVmEntityErr`): a config with `version:` newer than the binary reports "no kind:vm entity" instead of the real loader error. → **VM-box cutover task 4 (generic BoxRef resolver)**: surface the underlying `LoadUnified` error in the entity-resolve path.
2. **`vm destroy` of a snapshot-pivoted VM deletes the golden snapshot disk** while the registry entry (and any clone backing it) survives — dangling baseline hazard. → **VM-box cutover task 9 (check-vm-clone bed)**: snapshot-aware destroy path (metadata-only delete + refcount check) proven on the bed.
3. **Clone boot vs running base:** a clone cannot boot while the base VM is live on the pivoted snapshot file (qemu shared-write-lock). → **VM-box cutover task 8 (skills/docs)**: vms-catalog clone workflow documents "stop the base before booting clones".
4. **Clone does not inherit the base's ssh user** (adopted `base_user`/`ssh.user`) — the clone entity must restate `ssh.user`. → **VM-box cutover task 4 (generic BoxRef resolver)**: clone resolution inherits the base's ssh user by default.
