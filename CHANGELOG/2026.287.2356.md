# 2026.287.2356 — feat(vm)!: thread the request ctx through the emit path, drop the retired build-engine field (opencharly/opencharly#481 leg 19; supersedes #84)

## Summary

**Leg 19 of `opencharly/opencharly#481` (`plugin-vm`), and it supersedes `#84`.** Two changes, both compiler-forced by the landed contract, plus the two findings `#84`'s review raised — fixed here rather than inherited — **and the class-gate bed this lane owes.**

**1. The retired build-engine field is gone.** `resolvedConfig.BuildEngine` was carried from the contract's builder selector and only ever **written** — no reader in this repo consumed it. The value is gone from the contract (spec leg 1: the image builder is BuildKit, which is not a container engine), so the field and its initializer go; `RunEngine` stays and is what the callers actually use.

**2. The real request context is threaded through the emit path** — leg 3 made `deploykit.EmitVmBox*` take a `context.Context` first, so every call site was compiler-forced to move. This threads **`cmdCtx`, the context the plugin's invocation runs under**, from the drive and bake boundaries down through `emitVmBox`, `runVmBuildDrive`, `runBakePhase5` and the `bakeEmitBox`/`vmBuildDrive` seams — and through every test seam that stands in for them. That is the intent leg 3's change exists for: *the engine build is cancellable with the request that asked for it*.

**3 and 4 — `#84`'s findings 2 and 3, fixed in-tree:** `TestEmitVmBoxHonorsTheRequestContext` emits under an **already-cancelled** context and requires the abort; and `requireBuildkitDrive` guards the five emit-dependent tests so a host without the BuildKit toolchain **SKIPS visibly** instead of failing as though the code were broken (the sdk ships the same guard for its own tests; it is unexported there, so the SHAPE is reproduced here).

**5 — the class-gate bed, authored and run (round 1, finding 1).** See below; the previous decision to decline it as *"disproportionate"* was **wrong**, and the reviewer's reason is the rule: the change class follows **what the user can observe**, not the size of the diff.
