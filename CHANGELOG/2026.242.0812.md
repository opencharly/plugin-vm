# 2026.242.0812 — feat(vm): read the disk layout from the distro definition

## Summary

`plugin-vm#6` gave `EmitDiskBuildScript` the ability to build a btrfs subvolume layout and
to put the ESP somewhere other than `/boot/efi` — but **nothing could ask for it**.
`buildBootstrapDisk` hardcoded the layout, so the capability was unreachable.

`spec#72` added `#Distro.disk_layout`, so the shape can now be declared where it belongs:
on the **distro**, because it *is* the distro's identity. An ISO-installed Omarchy guest
always has `@`/`@home`/`@log`/`@pkg`, and always has its ESP at `/boot`.

### Nothing changes for any existing distro

A distro that declares no `disk_layout` leaves `EspMountPoint` empty (the emitter defaults
it to `/boot/efi`) and `Subvolumes` nil (a bare filesystem). That is the same guarantee
`TestEmitDiskBuildScript_NilSubvolumesIsByteIdentical` already pins at the emitter, and
`TestBootstrapDiskLayout_NoDistroBlockIsUnchanged` now pins it at the **mapping** too, for
both a nil `*DistroDef` and one carrying an empty struct — the two shapes a distro without
the block can actually take.

### The production mapping, executed live

An earlier revision of this PR was correctly blocked twice: the mapping was **copy-pasted**
into a test helper (so the tests would still have passed if production diverged), and the
tier claimed `fully tested and validated` while the changed branch had never run. Both are
fixed rather than argued down.

`DiskLayoutFromDistro` is now a named pure function that **`buildBootstrapDisk` and the
tests both call** — the mirror is deleted — and the live test runs that function plus the
script it emits against a **real partitioned disk**:

The test parses the `disk_layout` **exactly as authored in `charly/charly.yml`** through
`spec.DiskLayout`, so a field renamed in the schema breaks it.

It is guarded by `CHARLY_LIVE_DISK=1` because it needs a privileged container and loop
devices; CI has no business allocating those, and a test that silently no-ops would be
worse than one that says why it skipped.

**What the harness adapts, and what it does not.** A container runs no udev, so loop
*partition* nodes never appear and `mkfs.fat "${LOOP}p1"` fails with `No such file or
directory`. The preamble shims `partprobe` to create them with `kpartx` and symlink them to
the names the script uses. The script under test is **not** rewritten — it runs byte-for-byte
as emitted, including the real `parted` partitioning that plugin-vm#6's two-loop-device
proof could not cover.

## Rulebook compliance

- **R0 — skills first.** `/charly-internals:git-workflow`.
- **R1 — RCA every anomaly.** Four surfaced, all root-caused. (a) The import is
  `github.com/opencharly/spec/spec` — the package lives one level down, as
  `vm_move_aliases.go` already showed. (b) `#Subvolume` generates as `[]spec.Subvolume`,
  not `[]*spec.Subvolume`: CUE's `@go(...,optional=nillable)` applies to the optional
  *field*, not to list elements. (c) The live test produced empty output and failed in
  1.1s — `podman run` needs `-i` to attach stdin, which it did not have. (d) With stdin
  fixed it failed on `mkfs.fat: unable to open /dev/loop3p1`: the first shim hooked
  `losetup`, which runs BEFORE `parted` creates the table, so `kpartx` found no
  partitions. Hooking `partprobe` — the point where the table exists but has not been
  used — is the fix.
- **R2 — finish the whole cutover.** The repin, the mapping and the tests land together;
  the capability is reachable end to end as of this commit.
- **R3 — no duplication.** The mapping is ONE function, `DiskLayoutFromDistro`, called by
  both production and tests. The first revision inlined it in `buildBootstrapDisk` and
  mirrored it in a test helper — review caught that, and the mirror is deleted.
- **R4 — no workarounds.** No defaults are duplicated here: the emitter owns them, so a
  distro omitting the block and a distro that does not exist take the identical path.
- **R5 — delete legacy completely.** The hardcoded `DiskLayout{…}` literal is gone — it
  is replaced, not supplemented; there is no remaining path that ignores the distro.

  clean, which the teardown output shows. That is the disposable proof available to a
