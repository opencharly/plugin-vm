# 2026.269.2025 — feat(vm): add `charly vm retag <src> <dst>` for a stable box ref

feat(vm): add `charly vm retag <src> <dst>` for a stable box ref

## Summary

`charly vm build` tags its emitted VM box with the **wall-clock CalVer**
(`localhost/charly-<vm>:<YYYY.DDD.HHMM>`). A consumer that must **name** the image
statically — a `kind:kubevirt` `container_disk.image`, or any authored ref — cannot
know that tag in advance. This is the addressing gap (B1) that blocks the
`check-kubevirt-vm` R10 bed.

This adds a **retag verb**:

- **`charly vm retag <src> <dst>`** — resolves `<src>` the SAME way `cp-box` does
  (`container.ResolveDeliverableRef`: a short name elects the newest matching local
  image; a full ref passes through), tags it as the deterministic `<dst>`, and with
  **`--push`** also pushes `<dst>` so a cluster can pull it by that ref.
- `retagImage(engine, src, dst)` is the **one** tag primitive (a same-ref retag is a
  no-op; an empty destination is rejected). `pushVmBox` now calls it too — there is
  no second `tag` site.

Files: `vm_retag.go` (verb + primitive), `vm.go` (registered in the `vm` command
tree), `vm_retag_test.go`, `vm_box_emit.go` (pushVmBox shares retagImage).

### Runtime R10 target (producer-first)

`plugin-vm` is a **producer**. `charly vm retag` is a host-local command (it tags a
local engine image; it deploys nothing), so its live proof is the CLI run + the
changed-runner test above. The disposable bed that consumes this verb end-to-end is
**`check-kubevirt-vm`** (charly, plan WS-7.3), which pins `plugin-vm` at the tag
this PR mints, retags the built box to a stable ref, and boots it as a KubeVirt
containerDisk on a `disposable: true` target. Per producer-first landing that
consumer cannot precede this tag.
