# 2026.269.2343 — fix(vm): key the vm-build disk dir by the LEAF entity (RCA-F)

## Summary of changes

Fix `vm build` to key its disk directory by the **leaf** entity name, matching
every read path, and to resolve a namespace-qualified vm ref. This is RCA-F of
the `check-all-beds` roster RCA.

### RCA (8-step, measured live)

**Unexpected.** A namespaced VM bed (`charly.check-agentteams-vm`): `vm build`
passed, then `vm create` failed:

```
disk.qcow2 not found at image/<leaf>/disk.qcow2
```

**Mechanism.** Two naming conventions for one artifact:

- `vm build` wrote `vmshared.VmDiskDir(boxName)` — the **qualified** name
  (`charly.check-agentteams-vm`) for a namespaced bed;
- every READ path — `baseDiskPath`, `BuildClone`, `vm_diagnose` — uses
  `vmDiskDir(entityLeaf(entity))` — the **leaf** (`check-agentteams-vm`).

So the build wrote `image/charly.check-agentteams-vm/disk.qcow2` and the create
read `image/check-agentteams-vm/disk.qcow2`.

`resolveVmBuildEntity` also short-circuited on `uf.VM() == nil`, which checks the
vm **template** map (not the deploy), so a namespace-qualified ref bailed with
"no kind:vm entity" before the namespace-aware body lookup ran.

### Fix

- `vm build` keys the disk dir by `entityLeaf(boxName)` (via `vmBuildOutputDir`).
- Drop the `uf.VM() == nil` guard; resolve the body via `vmBuildEntityBody`
  (`uf == nil` guard + the namespace-aware `ResolveKindEntityBody`).
