# 2026.242.1323 — fix(vm): render the iso answers volume PER DOMAIN

## Summary

**A deploy's domain got no answers volume at all.** The per-domain seed branch handled only
`cloud_image`, so an `iso` source fell straight through it, `seedISOAbs` stayed empty, and
the domain was defined with just the blank disk and the installer cdrom. The installer found
no answers and fell back to its interactive wizard.

```go
// before
if perDomain {
    if spec.Source.Kind == "cloud_image" && spec.CloudInit != nil {
        seedISOAbs = filepath.Join(vmStateDir, "seed.iso")
    }
    // iso: nothing. seedISOAbs stays "". No volume is attached.
}
```

Confirmed on the defined domain — only `vda` and the installer on `sda`, no seed:

```
<disk device='disk'>  <target dev='vda' bus='virtio'/>   (the blank overlay)
<disk device='cdrom'> <target dev='sda' bus='sata'/>     (the installer ISO)
```

## How it was caught

**By `check-omarchy-iso-vm` on its very first run.** Every unit test passed and the direct
(non-deploy) `charly vm create` path worked correctly, because only a *deploy* takes the
per-domain branch. A negative control makes the point: deleting the fix again still
**compiles and still passes the whole suite** — the gap is invisible to the compiler, which
is exactly why the bed is worth having.

## The fix follows the rule cloud_image already states

That branch's own comment says why it exists:

> a deploy renders its OWN per-domain seed (per-domain ssh key + instance-id — two beds must
> NEVER share one seed, or their cloud-init keys/instance-ids collide)

An iso seed carries `authorized_keys`. Two domains sharing one is two guests sharing one SSH
key — identical reasoning.

**The obstacle** was that the answer *format* lives on the distro, and `vm create` has no
distro resolved. So `BuildIsoVM` now persists the rendered answers beside `seed.iso`
(`.seed-answers.json`), and create re-packs a per-domain volume from them.

**Only `authorized_keys` is per-domain.** Hostname, credentials, disk and partition geometry
describe the *install*, not the domain, and survive the re-pack byte-for-byte — asserted,
not assumed.

**An empty pubkey leaves the file in place** rather than removing it. On a distro that treats
`authorized_keys`' presence as "enable sshd and open the firewall", dropping it silently
produces an unreachable guest — worse than a stale key.

**Mode 0600 on the sidecar.** An encrypted install's answers carry the LUKS passphrase in
plaintext, because the installer needs it to create the volume. The volume itself is
world-readable once attached to a guest; this host-side copy need not be.

## How tested

```
$ go test -count=1 -run 'RepackPerDomainSeed|WriteSeedSidecar' ./
ok  	github.com/opencharly/plugin-vm/candy/plugin-vm	0.209s
```

Four tests: the key is swapped while every other answer survives; an empty key does not drop
the file; re-packing with no prior build errors with `charly vm build` named; the sidecar is
not world-readable.

**Live, on the bed that found it.** Before this change the domain had no seed and the guest
sat at the wizard. After it, the per-domain volume is attached on virtio —

```
<source file='.../charly-check-omarchy-iso-vm/seed.iso'/>
<target dev='vdb' bus='virtio'/>
```

— and the guest **installed itself unattended**: the per-domain overlay went from a blank
qcow2 to **6,167,068,672 bytes** with nothing typed.

**Full suite, `-count=1`:**

```
$ go test -count=1 ./...
ok  	github.com/opencharly/plugin-vm/candy/plugin-vm	2.043s
?   	github.com/opencharly/plugin-vm/candy/plugin-vm/cmd/serve	[no test files]
?   	github.com/opencharly/plugin-vm/candy/plugin-vm/params	[no test files]
```

`go build ./...` and `gofmt -l .` clean.

**What still does not work, and where it is routed:** the bed reaches an installed guest but
its post-install probe step does not complete. `source.install_timeout` is declared on the
`iso` arm and, like `kernel_args` before it, is **not implemented** — nothing extends the
readiness deadline to cover a multi-minute install.

That is **opencharly/plugin-vm#11**, filed with the measurement and with what the fix has to
decide (Omarchy *reboots* rather than powering off, so `#DistroInstaller.done`'s
`poweroff`/`marker_path` do not describe it; and widening the global readiness default would
make every other VM kind wait minutes before reporting a real failure).

It is not fixed in this tree because it is a different mechanism in a different seam — the
readiness bound resolved from `CHARLY_READINESS_*`, not the seed-attachment path this PR
touches — and the two changes share no code. This PR removes the blocker in front of it: with
no answers volume at all, no readiness deadline of any length would have helped.

## Rulebook compliance

- **R1 — RCA every anomaly.** The empty `seedISOAbs` was traced from the defined domain's XML
  back to the branch that skips non-`cloud_image` sources, not guessed at.
- **R2 — Finish the whole cutover.** Both halves of THIS mechanism ship together: the build
  persists the answers, create consumes them, and neither is useful alone. The one issue
  surfaced and not fixed here is routed to a named task, **opencharly/plugin-vm#11**, not
  deferred to "later" — it is a different seam (the readiness bound) sharing no code with the
  seed-attachment path this PR changes.
- **R3 — No duplication.** The re-pack reuses `vmshared.WriteLabeledISO`; the answers are not
  re-rendered, they are carried.
- **R4 — No workarounds.** The rejected alternative was sharing the entity's seed across
  domains — which "works" until two guests need different keys, i.e. it hides the defect.
- **R5 — Delete legacy completely.** N/A — additive; no path is replaced.
- **R6 — Git safety.** `git status` inspected before the commit; `grep -c '^replace'` on the
  committed `go.mod` is 0. No force-push, no direct push to `main`.
- **R7 — Prove behavior, not compilation.** The negative control is the point here: the fix
  removed still compiles and still passes every test. Behaviour was proven on a live guest.
- **R8 — Preserve emitted artifacts.** Both emitted artifacts are asserted — the sidecar
  round-trips byte-for-byte, and the re-packed volume is read back and inspected.
- **R9 — Binary equals source.** N/A for this repo — plugin-vm is a candy, not a binary, and
  this adds no runtime OS dependency.
- **R10 — Fresh disposable proof.** Exercised by `check-omarchy-iso-vm` (`disposable: true`)
  on a freshly created domain and overlay, destroyed afterwards. The bed does not yet pass
  end to end — see the `install_timeout` gap above — but the behaviour this PR changes was
  observed live in both directions.
