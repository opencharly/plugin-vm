# 2026.276.1503 — fix(vm): reclaim the per-domain state dir on `vm destroy --disk` (#64) + never delete the shared entity base (#65)

## Summary

Fixes two defects in `charly vm destroy --disk` that surfaced during a host disk-cleanup pass (108 stopped VMs destroyed; **~41G orphaned** across the two bugs).

- **#64** — The `libvirt` arm of `destroyVmDomain` returned after undefining the domain **without removing the per-domain HOST state dir** (`$VmStateRoot/charly-<domain>/` — the live `disk.qcow2` overlay, `snapshots/`, ssh keys, `seed.iso`); only the `qemu` arm did `os.RemoveAll(stateDir)`. So `charly vm destroy <libvirt-vm> --disk` printed success while orphaning the overlay (up to tens of GB per VM); it was reclaimed only by a **second** identical destroy, by accident, once `vmHolder`'s backend fallback reached the qemu arm.
- **#65** — `destroy <entity> --domain <deploy> --disk` ran `vmDiskDir(c.Box)` = `image/<entity>/` and `os.RemoveAll`'d it — the **shared read-only BASE every per-deploy overlay for that entity backs onto** (the site comment claimed "never the shared parent"; that claim was false for the `--domain` case). A deploy-domain `--disk` destroy silently corrupted every sibling domain.

## Changes

- `vm.go`
  - Extract `destroyVmDomainOnBackend(name, backend, stateDir, deleteDisk)` so the arm logic is unit-testable; `destroyVmDomain` delegates to it.
  - The `libvirt` arm now removes the per-domain state dir when `--disk` is set, via a shared `removeVmStateDir` (resolves through the ONE `vmshared.VmStateRoot`; the qemu arm's `stateDir` already derives the same way). `--keep-disk` is preserved (removal gated on `deleteDisk`). (#64)
  - Extract `removeEntityBaseDisk(box, domain)`: the entity base dir is removed **only on a direct entity destroy** (`domain == ""`); a `--domain` destroy removes only the deploy's own state dir, never the shared base. (#65)
- `vm_destroy_test.go` — `TestRemoveVmStateDir`, `TestDestroyVmDomain_LibvirtDiskRemovesStateDir` (#64), `TestDestroyVmDomain_LibvirtKeepDiskPreservesStateDir` (the `--disk` gate), `TestRemoveEntityBaseDisk` (#65).
