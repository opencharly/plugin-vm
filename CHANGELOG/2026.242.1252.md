# 2026.242.1252 — fix(vm): put an installer VM's answers on virtio, not a cdrom

## Summary

An unattended ISO install was reaching the guest, booting, and then **stopping at the
interactive wizard with nobody at the keyboard**. This is the **libvirt half** of the fix: the answers volume moves to **virtio-blk**
for installer VMs only. opencharly/sdk#197 is the qemu-renderer half; neither works alone.

## Root cause, from the guest's own scripts

Omarchy's `.automated_script.sh` runs `omarchy-cidata-load` on tty1. That script:

```sh
# The by-label symlinks come from udev, and on a fast boot this can run before
# device enumeration has finished. Wait for the queue to drain instead of
# racing it and silently dropping a headless install into the wizard.
udevadm settle 2>/dev/null || true

device=""
for label in cidata CIDATA; do
  [[ -e $by_label/$label ]] && { device=$by_label/$label; break; }
done
[[ -n $device ]] || exit 1
```

**`udevadm settle` drains only the queue as it stands.** A cdrom whose probe has not been
*queued* yet is not covered. The lookup misses, `omarchy-cidata-load` exits 1, the caller
falls back to `./configurator` — the interactive wizard — and the whole thing exits.

Note the script's own comment: it is explicitly defending against this exact failure. Its
defence is simply not sufficient for a SATA cdrom.

**It is a race, not a bad volume.** Running the same script a minute later finds the drive
and installs fine — which is how the earlier end-to-end proof was driven:

```
$ ls /dev/disk/by-label/
OMARCHY_202608  cidata
$ omarchy-cidata-load; echo LOADRC=$?
LOADRC=0
```

## The fix, measured both ways

virtio-blk enumerates far earlier and wins the race. Same seed, same ISO, same everything
else, only the bus changed:

| Seed attached as | Result |
|---|---|
| SATA cdrom | disk stayed at **197,248 bytes**, indefinitely — the wizard, then a shell |
| virtio disk | disk installed to **6,092,816,384 bytes**, **unattended**, and reached the installed system's greeter |

**This is a real fix, not a workaround.** No sleep, no retry, no polling, no serialization
hiding a race (R4). The device is presented on a bus that is enumerated before the consumer
looks, which is the actual missing condition.

## Scoped to installer VMs only

Guarded on `SeedISOPath != "" && InstallerISOPath != ""`. `cloud_image`, `bootc` and
`bootstrap` keep the cdrom: cloud-init finds a NoCloud source on either bus, it has never
raced here, and moving them would be a behaviour change to **every existing VM** in exchange
for nothing.

## Rulebook compliance

- **R1 — RCA every anomaly.** Root-caused by reading the guest's own scripts out of the
  ISO's squashfs, not by guessing. Five hypotheses were eliminated first with evidence
  (no video device, missing cloud-init `meta-data`, cdrom ordering, the GRUB default entry,
  the volume label) — all recorded in opencharly/distro-omarchy#4.
- **R2 — Finish the whole cutover.** Both renderers move together: this is the libvirt half,
  opencharly/sdk#197 is the qemu half, and neither works alone. The installer cdrom's target
  moves sda←sdb in the same change, since the answers leaving SATA would otherwise leave a
  gap.
- **R3 — No duplication.** One branch in the existing seed-attachment site; no parallel path.
- **R4 — No workarounds.** Explicitly not a sleep, a retry, or a poll. The missing condition
  was "the device is enumerated before the consumer looks", and that is what changed.
- **R4a — Fix the product first.** The alternative was documenting "run the installer
  manually a minute after boot", which would have made the defect permanent by making it
  look intended.
- **R5 — Delete legacy completely.** The cdrom path is not left behind as a fallback for
  installer VMs — it is the other arm of an if/else, reachable only by the source kinds that
  should keep it.
- **R6 — Git safety.** `git status` inspected before the commit; no force-push, no direct
  push to `main`.
- **R7 — Prove behavior, not compilation.** Two negative controls, plus a measured
  before/after on a real guest with a 6 GB difference in outcome.
- **R8 — Preserve emitted artifacts.** The emitted artifact is the libvirt domain XML,
  asserted in full in both tests — including that nothing is left occupying sdb.
- **R9 — Binary equals source.** N/A for this repo — plugin-vm is a candy, not a binary, and
  this adds no runtime OS dependency.
- **R10 — Fresh disposable proof.** The measurement ran on a freshly created 40 GiB qcow2
  and fresh NVRAM, twice, changing only the bus. It unblocks the `disposable: true`
  `check-omarchy-iso-vm` bed, which could not exist while the install needed a keystroke.
