# 2026.272.2040 — fix(plugin-vm): adopt the sdk ctx requirement on the deploy-config family

## Summary

`sdk#288` (`v0.2026271.915`) added a **`context.Context` parameter** to the `deploykit`
deploy-config family, removing the fail-open default so each invocation resolves its OWN
per-box overlay via `kit.DefaultDeployConfigPath(ctx)`. Without a bumped `sdk`, this plugin's
compiled-in candy cannot build against the `#717` fix version (`sdk v0.2026272.1813`), which
blocks `opencharly/charly#733` → `#714`. This PR adopts `ctx` in `plugin-vm` and bumps
`sdk`/`spec` to the ctx-ready tags.

### Threaded the REAL ctx (no fabrication)

`plugin-vm` is a compiled-in `command:vm` plugin whose provider dispatches via
`Invoke(ctx, req)`; that genuine ctx is stashed package-side by
`setCommandContext(ctx, exec)` into `cmdCtx` at the Invoke entry — and **this very file already
uses it**: `vmLoadDeployConfig` passes `cmdCtx` to
`loaderkit.LoadHostDeployConfigViaExecutor`, and `vmFetchLoaderPrimaries` passes it to
`cmdExec.HostBuild(cmdCtx, …)`. `hostConfigPersist`'s three deploy-config writes were the only
call sites still missing it. `context.Background()` is **not** used: the ctx selects the
invocation's overlay.
