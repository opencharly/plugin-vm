# 2026.253.1809 — fix(vm-create): the entity-name-keyed paths use the LEAF for a namespace-qualified ref

## Summary

The vm-create + diagnose paths looked up the base disk + seed under the QUALIFIED entity name (omarchy.check-charly-omarchy-vm), while the vm-build clone drive writes them under the LEAF (check-charly-omarchy-vm — the name as authored in the owning repo). The qualified ref is the cross-repo reference; the leaf is the entity-dir key. All entity-name-keyed paths now strip the namespace prefix (entityLeaf): the base disk (extracted as baseDiskPath), the base seed, the per-domain seed repack, and the diagnose seed path.

**Tests (both gate the changed behavior):**
- TestBaseDiskPath: the vm-create base-disk path for a namespace-qualified ref resolves to the LEAF-keyed path; the local path is unchanged. Fails without the leaf-stripping.
- TestEntityLeaf (from #32): the leaf-stripping itself.
