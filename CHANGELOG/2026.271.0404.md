# 2026.271.0404 — feat(vm): vm bake --domain + vm create --keep-disk (reland of #57)

## Summary

**Supersedes plugin-vm#57** (auto-closed after 5 unsigned BLOCKs) — carried forward on a clean thread with **every finding fixed in one commit**.

Add **`charly vm bake --domain <deploy>`** + **`charly vm create --keep-disk`** so a bed drives the bake against a **disposable per-deploy domain** instead of the shared `kind: vm` entity.

**Why.** `kubectl`-style entity-vs-deploy: a `kind: vm` ENTITY cannot carry `disposable:` (it is a DEPLOY property). #55 made the bake boot a per-domain overlay, but keyed the snapshot registry and every create/stop/destroy on the **entity** — so a bed could only bake by mutating the shared entity's goldens/disks. `--domain` keys them to the caller's deploy (a `vm:` deploy the caller declares `disposable: true`); its **golden** is captured there (`vm snapshot create … --domain`, existing) and its **disk** is the golden's backing. `--keep-disk` makes the bake's create **non-destructive** so that backing survives (the create used to remove+overlay it).

- `--domain` absent → the derived `<entity>-bake` (the golden is captured on that domain); the create is a fresh overlay as before.
- `--domain X` → the domain is `X` (the destroy stays `KeepDeploy: true`).

Files: `candy/plugin-vm/vm_bake.go` (`--domain`, `bakeDomainName`, `bakeCreateCmd`), `candy/plugin-vm/vm.go` (`vm create --keep-disk`), `candy/plugin-vm/vm_create_orchestrate.go` (the non-destructive create), `candy/plugin-vm/bake_clone_source_test.go` (`TestBakeDomainName`, `TestBakeCreateCmd`).

### `--domain` is on `vm bake`; `--keep-disk` is a `vm create` field

To be exact (the prior body conflated them): the user-facing flag is **`vm bake --domain`**; the bake sets the **`VmCreateCmd.KeepDisk`** field internally (via `bakeCreateCmd`). There is no `vm bake --keep-disk` flag.
