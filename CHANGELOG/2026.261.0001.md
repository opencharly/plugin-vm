# 2026.261.0001 — fix(deps): adopt the shared sdk/spec pins so the plugin builds for 32-bit ARM

## Summary of changes

Adopts the fixed shared `sdk`/`spec` pins so this plugin builds for **32-bit ARM (armv7)**, and exercises the re-pinned plugin live.

- `README.md`: a Platforms section documenting that the module now builds for `linux/arm/v7` (the static cross-build command), the platform this change enables.
- `candy/plugin-vm/go.mod` + `go.sum`: `sdk` v0.2026258.1713 → `v0.2026260.1434`, `spec` v0.2026257.1817 → `v0.2026259.2033`. No source change. The branch carries two commits — the pin adoption and the README update — which the org's squash-merge collapses into one.

- `go.mod` — the two contract pins (`sdk`, `spec`; `spec` is a DIRECT require in this module), plus the `golang.org/x/*` bumps whose width the sdk pin carries:
  - DIRECT requires: `crypto`, `term` (no `// indirect` marker in the file).
  - `// indirect` requires: `net`, `sys`, `text`.
- `go.sum` — the same two contract pins, plus the full transitive `x/*` refresh: `crypto` v0.52.0→v0.54.0, `mod` v0.35.0→v0.37.0, `net`, `sync` v0.20.0→v0.22.0, `sys`, `term`, `text`, `tools` v0.44.0→v0.47.0.
- No module-identity change: this module's `go.sum` already carried `plugin-egress/candy/plugin-egress v0.2026237.1419` and `plugin-init/candy/plugin-init v0.2026237.1424` at the base — those lines are unchanged CONTEXT in the hunk, not part of this PR.

**Root cause:** `sdk/buildkit` did not compile for 32-bit targets — `syscall.Statfs_t.Bsize` is `int32` on `arm`/`386` but `int64` on `amd64`/`arm64`, so `buildkit/privileged_runner.go`'s `int64(st.Bavail) * st.Bsize` was a type mismatch off the 64-bit targets (opencharly/sdk#262, fixed in opencharly/sdk#263, merged tag `v0.2026260.1434`). Every module importing `sdk/buildkit` — this plugin included — therefore failed to build for armv7 until its own sdk pin moved.

**Closes / relates to:** depends on `opencharly/sdk#263` (merged), closes the armv7 gap tracked as `opencharly/sdk#262`. Part of the armv7 delivery for `opencharly/plugin-jetkvm`.

**Breaking change + rollback:** `none` — a dependency pin with no API or CLI change. Revert the merge to roll back.
