# 2026.260.1949 — fix(vm): name-first schema writes, retire the clone surface, add the guest-ping op

## Summary

Five same-theme fixes in `candy/plugin-vm` — all removing/honouring the schema-compaction
contract, plus the `guest-ping` readiness op its consumer (`opencharly/plugin-deploy-vm#18`)
needs.

1. **`fix(import)` — the name-first node.** `charly vm import` wrote a top-level `vm:` map with
   flat `source:`/`ram:`/`cpus:` keys — the named child-node shape **deleted** by the
   schema-compaction cutover. The loader HARD-REJECTS it (`node "vm": no kind discriminator`),
   so the command produced a config that could never load; `cpus:` also never matched the schema
   field (`cpu:`). Now it emits `<name>: { vm: { … } }`, spells `cpu`, and the update path
   locates `<name>.vm`.

2. **`refactor(vm)` — delete the retired clone surface.** `charly vm clone` is retired (the clone
   is authored on the DEPLOY via `from: <src>:<snapshot>`), but `VmCloneCmd` still advertised a
   live `--from`/`--build`/`--cloud-init-clean` surface and a "writes vm.yml" docstring. Reduced
   to a hard-error verb whose hidden flags keep parse compatibility. Removed the dead
   `findOrCreateMapEntry` helper.

3. **`fix(import)` — normalize the machine enum (live-caught).** Exercising
   `charly vm import` against the rebuilt binary on a real domain surfaced that the writer copied
   libvirt's raw `machine` type (`pc-q35-11.1`) verbatim — which the schema's closed enum
   (`q35`|`virt`|`i440fx`|`pc`) rejects, so the emitted `charly.yml` failed to load. `mapOSToSpec`
   now normalizes it (`normalizeImportedMachine`), dropping an unknown value rather than emitting
   an invalid one.

4. **`feat(provider)` — the `guest-ping` internal op.** Checks the DOMAIN STATE and pings the
   qemu-guest-agent, returning a TERMINAL vs TRANSIENT verdict. ONE `terminalDomainState()`
   predicate backs BOTH the `guest-ping` verdict AND the `domain-state` reply's new
   `state`/`failed` fields, so "which states are terminal" has a single definition.

5. **`fix(docs)` — the bootstrap hint must show the name-first shape it enforces.** The two
   `no kind:vm entity` error hints (`candy/plugin-vm/vm.go:220`,
   `candy/plugin-vm/vm_build_resolve.go:96`) still instructed operators to write the RETIRED
   shape — a top-level `vm:` map containing a `%s-bootc:` child — i.e. exactly the shape Summary
   item 1 documents the loader HARD-REJECTING. They now spell `charly.yml` (the per-kind authoring
   root) and show the NAME-FIRST node (`%s-bootc:` wrapping `vm:`), matching the shape the loader
   enforces. **RCA:** the same mechanical `vm.yml`→`charly.yml` prose sweep that produced items 1–2
   re-spelled the file name but copied the retired nesting order forward; a user following the hint
   would emit a config that cannot load, the same defect class as item 1, so the fix is the shape,
   not just the string.
