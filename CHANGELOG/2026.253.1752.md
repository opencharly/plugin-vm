# 2026.253.1752 — fix(vm-build): the namespace-qualified vm entity resolution (the runtime counterpart)

## Summary

resolveVmBuildEntity used the local-only uf.VM() lookup — a bed cloning from a git-linked namespace golden (omarchy.check-charly-omarchy-vm:golden) validated GREEN at load (sdk #246) but failed vm-build with "has no kind:vm entity". The body lookup now uses loaderkit.ResolveKindEntityBody (sdk #247) — the canonical namespace-aware runtime surface: a local OR namespace-qualified (ns.entity) vm template resolves here.

**Dependency bumps (both accounted):**
- github.com/opencharly/sdk v0.2026250.527 → v0.2026253.1714 (the namespace-aware runtime resolution, sdk #247)
- github.com/opencharly/spec v0.2026250.523 → v0.2026250.2036 (transitive via go mod tidy)

**Tests (both gate the changed behavior):**
- TestVmBuildDeployFromHop_Qualified: the namespace-qualified hop (omarchy.check-charly-omarchy-vm → omarchy.omarchy-vm) resolves via the canonical DeployTargetEntity; the unqualified form stays local-only.
- TestResolveKindEntityBody_Qualified: the CHANGED LINE directly — loaderkit.ResolveKindEntityBody(uf, "vm", "omarchy.omarchy-vm") resolves the namespace template body; the unqualified form stays local-only. Fails without sdk #247.
