# 2026.244.1307 — fix(vm): revert-and-start stops the domain FORCEFULLY

## Summary

Fixes the `charly vm snapshot revert-and-start` composite (landed in #16): the revert requires the domain OFFLINE, but the composite's stop was a graceful ACPI shutdown — which can hang on a desktop guest (the omarchy desktop's session blocks ACPI poweroff; the 3-minute stop grace expired with the domain still running, and the snapshot-anchored check-run lane failed at the revert).

The stop is now FORCEFUL (`stopVmDomain(name, true)`): it destroys the domain but PRESERVES the disk + definition, which is exactly what the revert + restart need. An already-stopped domain remains a clean no-op; an absent VM still fails (never false-succeeds).
