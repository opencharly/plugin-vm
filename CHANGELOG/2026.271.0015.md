# 2026.271.0015 — fix(vm): bake boots a per-domain overlay + flattens before emit (closes #54)

## Summary

Fix **`charly vm bake`** so the produce half runs end to end. **Closes #54.**

**The defect.** The bake's phase 1 called `applyCloneDriveSource(vmSpec, c.Box, c.FromSnapshot)` (self-clone) and `BuildClone(c.Box, …)`, which writes the clone overlay to `vmshared.VmDiskDir(<entity>)/disk.qcow2`. That path **is the entity's own live disk**, and `createExternalSnapshot` makes the entity's golden snapshot an overlay **backing onto** it — so the clone overwrote the golden's backing file and produced a **circular qcow2 backing chain** (`qemu-img: Backing file … creates an infinite loop`), refused by the bake's own staleness guard. A second defect sat in phase 5: it emitted the *snapshot overlay*, not a flattened disk.

**The fix — two changes:**

1. **No self-clone: boot a per-domain overlay.** The bake now boots the entity with a distinct bake DOMAIN (`<entity>-bake`) via `VmCreateCmd{Box, Domain: bakeDomain}`. Its disk is a per-domain overlay onto the entity's frozen base, so the base — and the golden that backs onto it — stay immutable. `--from-snapshot` still names the golden, and the bake verifies it exists (`LookupSnapshot`). The guest-agent enable is **best-effort** (the bake no longer freezes a snapshot).
2. **Flatten before emit.** Phase 4 force-stops the bake domain and `qemu-img convert`s its overlay into a standalone `baked-flat.qcow2`, which phase 5 emits (`--container-disk` → `/disk/disk.img`) and pushes. The bake domain + disk are torn down after the emit.

Files: `candy/plugin-vm/vm_bake.go` (the new phases + `bakeWorkingDisk` + `qemuImgConvert`), `candy/plugin-vm/bake_clone_source_test.go` (`TestBakeWorkingDisk` replaces the stale self-clone-wiring gate).
