# 2026.319.0925 — feat: pass the threaded kind gates to the defaults seam

## Summary

The caller half of the RCA's step 3: `ApplyCueDefaults` takes the threaded snapshot (opencharly/spec#326), and this repo hands it the `KindGates` the host declared — so a body whose authored schema moved into a plugin is reachable when a loader-side helper fills defaults.

**The defect this closes:** the fill resolved the vm body through the base contract's declaration for the kind, which is the resolved ENVELOPE (`#ResolvedVm` — plain post-default scalars, `firmware!: string`) and not the authored `#Vm` the serving plugin ships. Six `applyCueDefaults` tests in `opencharly/charly` failed with `firmware: cannot convert non-concrete value string`; the host's gates are how the authored declaration reaches that fill.

**What this round changed.** The previous round's seam test could not fail: it asserted only the absence branch (`cmdExec == nil` ⇒ nil), which passes unchanged if `vmKindGates()` stops sourcing the snapshot entirely.

- `kindGatesFromHost` — the host-ASK behind a package var, so the seam's POSITIVE branch is provable in this repo; every production read still goes through `loaderkit.LoaderThreadedViaExecutor`.
- `applyVmDefaults` — the defaults fill NAMED, so the suite drives the production call (the sourced gates reaching the fill) instead of a gate map the test built for itself. `hostConfigResolve` now calls it.
- `vmKindGates` and `setCommandContext` each carry their own doc comment again (the previous round had left `setCommandContext`'s comment above `vmKindGates`).
