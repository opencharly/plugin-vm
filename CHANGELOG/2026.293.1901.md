# 2026.293.1901 — fix(vm): carry the project dir into the builder auto-build request

## Summary

Head `feab2b145ef431d0810cc599f9d0f4f3db474cce`.

`charly vm build` auto-builds a missing builder image, but the auto-build had no project context: `ensureBuilderImageBuilt` marshalled `spec.BuildRequest{Boxes, IncludeDisabled}` without `Dir`, so the box build resolved no context and the drive failed with `buildkitdrive: build: no context` — while the same box builds cleanly through `charly box build` (the CLI passes the dir).

The fix carries the plugin's project dir (`os.Getwd()`, the pattern every other path resolver in this plugin uses) through a new pure `builderAutoBuildRequest(builderRef, dir)` helper. Two tests pin it: `TestBuilderAutoBuildRequestCarriesTheProjectDir` pins the request shape, and `TestAutoBuildCallSiteCarriesTheProjectDir` pins the CALL SITE (it scans `vm_build_resolve.go` for the `os.Getwd()` resolution and the helper call — proven RED on the pre-fix source where both patterns are absent, GREEN here). The `plugin-build` sibling (`bootstrap.go`'s auto-build) has the same shape and is called out in #87 for the same treatment.

## How tested

The repo gate on the final tree:

```console
$ go build ./...

$ go test -run TestBuilderAutoBuildRequestCarriesTheProjectDir .
```

The live auto-build path could not be exercised end to end on this host, and I am stating exactly why instead of implying otherwise:

1. The builder image (`cachyos-pacstrap-builder`) is already in local storage, so the auto-build never fires. `charly clean --invalidate 'cachyos-pacstrap-builder'` removed 0 tags (the auto-built image carries no charly CalVer labels for the invalidator to match), and the `--images` retention kept it (0 tags removed, `keep_images=0`).
2. With the image present, the bed reaches its real blocker: `charly check run check-cachyos-vm` fails at `building bootstrap VM disk: insufficient free space on /tmp/charly-priv-…: 26.1 GiB free, 27.0 GiB required` — this host's `/tmp` is a 31 GiB tmpfs. Filed as distro-cachyos#145.

So the live `vm build` runs on this tree used the pre-built builder (the auto-build branch not taken); the changed request shape is pinned by the test above, and the pre-fix failure is captured verbatim in #87 (`auto-building builder image "cachyos-pacstrap-builder": building arch.arch: buildkitdrive: build: no context`). A green end-to-end auto-build needs a host that can hold the 27 GiB VM disk (distro-cachyos#145).
