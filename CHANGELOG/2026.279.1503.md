### What this head does

Every context-less libvirt RPC the `charly vm create`/`start`/`destroy` path reaches is now wrapped in `boundedRPC`/`boundedRPCValue` (the existing helper), each with its **own** call-site guard:

1. **`defineAndStartDomain`'s reconcile lookup** calls `c.lookupDomain` (bounded), and **`ensureDomainSocketDirs`** reads the domain XML through the bounded `c.getDomainXML` (it previously called `l.DomainGetXMLDesc` directly).
2. **`activeDiskPath` reuses `c.getDomainXML`** (no re-inlined wrapper).
3. **`defineDomain` / `createDomain` are the single bounded helper per RPC** (R3) — shared by `defineAndStartDomain`, `redefineDomain`, `startDomain` — so each RPC has exactly one bound and one guard.
4. Both of `defineAndStartDomain`'s own RPC legs have **separate** call-site guards (`define and start domain define` / `_create`), driving the method itself with sibling seams released.
