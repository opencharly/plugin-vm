# 2026.269.2256 — feat(vm): emit + push a containerDisk from the in-guest candy bake

## Summary

`charly vm bake` (materialize → boot → apply layers in-guest → freeze) is the **produce path for a Cua Fleet / KubeVirt image**: the in-guest candy bake (the `layer-cua` set) is exactly what `charly vm build` cannot bake — `build` materializes a disk, it does not install candies into a running guest. But the bake's phase 5 hardcoded the default in-image path (`emitVmBox(..., "")` → `/disk.qcow2`) and had no push, so the **baked** artifact could not be delivered as a containerDisk. (`charly vm build --container-disk --push` and `charly vm retag --push` already cover the plain-disk case — plugin-vm#43 / v2026.269.1932 and v2026.269.2025.)

This closes the bake gap, reusing the existing primitives:

- **`charly vm bake --container-disk`** — emit the frozen disk at `deploykit.ContainerDiskPath` (`/disk/disk.img`), via the SAME `boxInImagePath` flag→path mapping `vm build` uses.
- **`charly vm bake --push <ref>`** — deliver the baked box via the ONE push primitive `pushVmBox`.

Both reuse `boxInImagePath` + `emitVmBox` + `pushVmBox` — **no new emitter, no second push, no new wire type, no new dependency**. Phase 5 is extracted into `runBakePhase5` with the emit/push seams as package vars (the `engineCmd` precedent) so the flag wiring is unit-testable without a live engine or a full bake.

It also **locks the containerDisk media-type contract**: the live push tests now re-pull the pushed ref and assert its single layer is `application/vnd.oci.image.layer.v1.tar+gzip`. buildah's *local* layer is the uncompressed `…v1.tar`; the push compresses it on the wire, so the delivered media type is what Fleet/KubeVirt see — and it is now asserted, not assumed (plan risk 1).

### Files changed

- `candy/plugin-vm/vm_bake.go` — the two flags; phase 5 extracted to `runBakePhase5` (+ the `bakeEmitBox`/`bakePushBox` seams).
- `candy/plugin-vm/vm_bake_test.go` — `TestRunBakePhase5` (flag wiring) + `TestRunBakePhase5_Live` (the changed path, live).
- `candy/plugin-vm/vm_box_emit_test.go` — `TestPushVmBox_Live` now asserts the pushed `+gzip` layer; adds the pure `pushedLayerMediaType` helper.

No `charly.yml` change: the grammar is prescanned from the Go command struct, and no provider/verb is added.
