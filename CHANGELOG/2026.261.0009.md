# 2026.261.0009 — docs: scope the armv7 note to the installed charly (R4a)

## Summary of changes

Fixes the `## Platforms` note added in #37 so it complies with **R4a** (the product-first rule for reader-facing commands).

- `README.md`: the note previously told the reader to run
  `GOOS=linux GOARCH=arm GOARM=7 CGO_ENABLED=0 go build ./cmd/serve` — a
  reader-facing instruction requiring a Go toolchain and a checkout of this
  repository, with a repo-relative path and no working directory. R4a forbids a
  command that needs more than the installed `charly` binary outside the install
  page. It now states the property instead: `charly`'s loader host-builds this
  plugin with `CGO_ENABLED=0`, so the artifact is a static binary that an armv7
  appliance without a glibc toolchain (e.g. a JetKVM's uClibc userland) runs.
  No command, no repo-relative path, no companion tool.

**Closes / relates to:** follow-up to `opencharly/plugin-vm#37` (which introduced the non-compliant text and merged before the fix landed on its branch).

**Breaking change + rollback:** `none` — a documentation correction. Revert the merge to roll back.
