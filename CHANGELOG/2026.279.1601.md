# 2026.279.1601 — fix(vm): bound every verb:libvirt introspection RPC + the screenshot stream, each with its own call-site guard (#73)

## Summary

The `#800` fix (`plugin-vm#70`) and its completion (`plugin-vm#74`) bounded every context-less, timeout-less go-libvirt RPC on the **`charly vm create/start/stop/destroy` lifecycle path**. The **`verb:libvirt` introspection surface** and the provider's introspection ops reach the *same class* of RPCs and were not in that cutover's scope — so a wedged `virtqemud` still hung any `libvirt:` check verb exactly as it used to hang `charly vm destroy`. This PR bounds them (closes `#73`).

go-libvirt has **no request timeout** (the premise of `#800`) and sets **no socket deadline anywhere**, so any of these calls blocks forever against a wedged daemon.

### What changes

- **New `libvirt_bounded.go`:** 13 bounded methods + 1 bounded package function, each a `boundedRPC`/`boundedRPCValue` around a `raw*` seam (the `#74` pattern): `listAllDomains` (`ConnectListAllDomains`), `domainInfo` (`DomainGetInfo`), `domainXML` (`DomainGetXMLDesc`, flags-aware), `sendKey` (`DomainSendKey`), `updateDeviceFlags` (`DomainUpdateDeviceFlags`), `qmpCommand` (`QEMUDomainMonitorCommand`), `listSnapshots`/`snapshotCreateXML`/`snapshotLookupByName`/`snapshotXMLDesc`/`revertToSnapshot`/`snapshotDeleteByHandle` (the snapshot RPCs), `screenshot` (`DomainScreenshot`), and `agentCommand` (`QEMUDomainAgentCommand`).
- **Every call site routed:** `libvirt_cmd.go` (list, info, screenshot, send-key, passwd, qmp, domain-xml, events, the four snapshot verbs), `provider.go` (`domain-xml`, `list-all-domains`), `libvirt_guest_agent.go` + `vm_target.go` (guest ping), `vm_snapshot_libvirt.go` (external snapshot create/delete/revert), `vm_libvirt.go` (`listCharlyDomains`).
- **`DomainScreenshot` is special (streaming).** It is the ONE stream call, and a per-call `boundedRPC` would abandon a blocked goroutine **every frame** in the session recorder's 2 s poll loop. So: (a) the screenshot RPC gets a `screenshotBound` (1.5 s — *below* the frame interval) so a wedge is dropped, not serialized; (b) its `virsh` fallback runs under `CommandContext` with the same bound; (c) the recorder's `writeFrames` now **stops after `recorderConsecutiveFailLimit` (5) consecutive screenshot failures** instead of polling forever, and `captureSession` distinguishes a real writer failure (`errRecorderWriterFailed`) from a display/daemon stop.
- The guest-agent bound is the agent's own in-band timeout **plus** a `libvirtProbeBound` margin, so a healthy agent is never cut early.
