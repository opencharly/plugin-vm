# 2026.279.1228 — fix(vm): prune old VM box tags after `charly vm build` (parity with box build; charly#808)

## Summary

`charly box build` runs a **post-build retention prune** (`pruneAfterBuild` → `verb:retention`, `BuildPrune`) that bounds the per-run image tags. **`charly vm build` did not prune at all**, so its per-run `localhost/<box>:<CalVer>` box tags accumulated without bound (opencharly/charly#808 — measured 24+ tags of one bed box).

`runVmBuildDrive` now calls **`pruneAfterVmBuild`** after a successful box emission — the **SAME** retention engine, reached the **SAME** way (`verb:retention` over the reverse channel, `sdk.OpRun`), best-effort warn-only, exactly mirroring `candy/plugin-box`'s `pruneAfterBuild` (R3: one engine, no second implementation).

This is the **companion** to `opencharly/sdk#345`: that PR stamps the `ai.opencharly.box` retention-group label on VM boxes (without which retention cannot see them); this PR makes `vm build` actually invoke the prune. Together they reclaim the bloat.
