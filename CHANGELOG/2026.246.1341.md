# 2026.246.1341 — feat(vm): the layered VM bake — charly vm bake

## Summary

Add the layered VM bake (cutover task 6): `charly vm bake <clone-entity> [--candy layer,...]` — the VM analog of the pod overlay Containerfile. A `source.kind: clone` entity is materialized (`BuildClone`, the base), the domain boots via the standard create path, the entity's layers are applied **in-guest via the SHARED InstallPlan IR** (delegated to the existing `charly fleet add vm:<name>` walk — the build drive cannot construct the guest SSH executor + plan machinery plugin-side, so with `--candy` the bake prints the exact fleet-add command and requires it applied before the freeze; re-run without `--candy` after applying), a consistent snapshot freezes the baked state, and the box image wraps it (`emitVmBox`). The domain is stopped after baking — the box is the artifact.

- `VmBakeCmd` + `Bake` wiring in `VmCmd`
- phases: build → boot → (layer apply, delegated) → snapshot → emit
- tests: `TestSplitCsv`, `TestBakeRequiresCloneKind` (the clone-source guard decision)

### Live execution (phases 1-2) + the fixes they drove

Built a dev charly binary from this branch (local replace of the plugin-vm module) and ran `charly vm bake clone-vm` against a real libvirt VM (a clone of the task-1 base's golden snapshot):

```
$ charly vm bake clone-vm
bake "clone-vm": phase 1 — materializing the base (clone)
bake "clone-vm": phase 2 — booting the domain
Generated SSH keypair in .../charly-clone-vm
Created VM charly-clone-vm (libvirt session)
```

Phases 1-2 executed live (base materialized on the golden snapshot, domain booted). The live run drove THREE in-tree fixes, each RCA'd:

1. **Vacuous test**: the clone-kind test asserted a string comparison, never the guard — extracted `requireCloneSource` and the test now drives the REAL guard (would fail if removed).
2. **Agent-before-freeze**: the strict snapshot freeze requires qemu-guest-agent reachable, but the domain was just booted — added a bounded `waitForAgentConnect` before phase 4.
3. **Agent-enable + subprocess ssh**: the re-materialized clone disk wipes any prior in-guest agent enable, so the bake must enable it after boot; `VmSshCmd.Run` uses `syscall.Exec` (it REPLACES the process — the first cold-boot ssh reset killed the whole bake, live-observed), so `enableGuestAgent` is a subprocess (`exec.Command`).

The full snapshot+emit chain on a clean boot is the cutover task-9 bed (check-vm-clone), which builds a fresh base, snapshots, clones, and bakes on a disposable: true target with the in-development binary.
